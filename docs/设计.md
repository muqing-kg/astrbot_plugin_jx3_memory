# 设计

## 一、目标

聊天里冒出一个剑网3 的词，模型知道那是什么，能用玩家的话接下去。

不做的事：不做问答命令、不做关键词触发、不抢消息；不给人格设定，插件只提供事实；查不到就说不清楚，不暴露内部机制。

## 二、检索

不预先灌输，按需查：模型要回话时，先只拿当前这条消息去碰词表，碰到才给条目；当前句一个都没碰着，才回看最近几条历史（给「这个呢」「那个怎么打」这类短句用）。

- 匹配是**字面**的：首字分桶 + 子串判定，长词优先。词表全在内存，单条消息通常 1–5 毫秒。
- 英文缩写不分大小写（「jjc」能命中「JJC」），中文不受影响。
- 不用向量：召回不准时塞错资料比不塞更糟。
- 多段文本之间用分隔符隔开再匹配，避免上段结尾与下段开头拼出并不存在的词。
- 词表是 `entry` 的主名加 `term` 里的别名，命中别名归一到主名（「跳车」→「跳车狗」）。简称不收，聊天里就接不住。
- 同一句里天差地别的几个词会各给一条，但名字互相包含的只留一条（「长安城」与「长安」）。
- 同名跨类型只留一个，顺序：心法 > 技能 > 副本 > 首领 > 通识 = 资料片 = 地图 = NPC = buff > 宠物 > 成就 > 任务 > 公告 > 物品。
- 物品、任务、成就里的两字名不进词表，「龙渊」这类既是地名也是物品名。通识词条不受限，「玄晶」「低保」本身就是两字，照常进表。
- 一个词挂了几十条条目的（「25人英雄」挂 356 条成就）直接丢弃：它一出现就会把整句里不相干的东西全捞出来。
- 别名来源两类：心法自动去后缀（紫霞功 → 紫霞），副本名按「·」切段（冰火岛·荒血路 → 荒血路），其余靠手工表补。

## 三、注入

落点是 `req.extra_user_content_parts`，每块 `mark_as_temp()`：只对本次请求生效，不写进对话历史，也不改系统提示词。

每轮固定先放一句，跟这轮聊什么无关：

```
[剑三·长期有效] 你玩了很多年剑网3。聊到剑三的东西按你知道的说，别猜、别编；
不清楚就说不清楚。不用主动科普，别人问了再讲。
```

命中条目后再接一段，一段话说完，不换行、不编号：

```
[剑三资料·仅用于理解，禁止原样输出] 对方提到的这些你本来就懂，用得上就用自己的话说一句，
别照抄、别念条目、别说「我查了一下」；对方没问含义就别主动解释。黑工：周常副本只能打一次……
```

- 第二人称，不编号、不标来源、不提示条数。整块连成一段：一行一条的排版会被模型学去，回话也分行。
- 每条摘要 60 字以内，按句读收口，不留半句。
- 双闸门预算：条数上限 5、字数上限 1200，任一先到即停，塞不下的整条丢掉不截半句。
- 同一会话里给过的条目不再重复给；全都给过时仍留一条，免得模型手里空着只能编。
- 被预算或去重挤掉的条目不算「给过」，下一轮还能再给。

正文只在被点名问时给：消息里出现「怎么」「在哪」「攻略」这类问法，并且这条是 @ 机器人、带唤醒词或私聊，才给命中的条目补一段正文，最多 120 字。群里插话只给摘要——插话时模型是随口接一句，塞四百字攻略进去只会让它念一遍。

正文取开头时会跳过玩家写的自述和寒暄（「本文截止于…」「有疑问请微博私信」「前言」「副本开放」「掉落品质」这些话），否则一百二十字的预算全被它吃掉，一句机制也没有。

## 四、存储

三个 SQLite 文件，随仓库一起下发，零第三方依赖：

| 文件 | 内容 |
|---|---|
| `data/memory.sqlite3` | `entry` 名字与摘要、`term` 检索词表、`news` 公告原文 |
| `data/memory_detail.sqlite3` | `detail` 正文：攻略、任务剧情、奇遇流程、副本打法 |
| `data/memory_attr.sqlite3` | `attr` 详细属性：装备、技能、奇穴、副本首领 |

- `entry(id, kind, name, brief, meta)`，`(kind, name)` 唯一。
- `term(word, entry_id)`：主名与别名混存，启动时一次性装进内存词表，之后每次请求只走内存匹配。
- 摘要生成时跳过正文开头的栏目小标题；正文为空才退回编辑备注。
- 正文按类目查：任务查 `quest`、奇遇查 `serendipity`、副本查 `fb`，其余查攻略帖。同名不同类的东西（任务「龙渊泽」与副本「龙渊泽」）不会互相串。副本题材的攻略单独一池——攻略库里标题带副本名的帖子全是成就做法（「声望·冰火岛·荒血路」「无伤 XX！」），拿来当打法就是答非所问。
- 副本攻略同名多篇时取最长那篇：最新的那篇常是活动通知或一两句话的碎念，真正的打法都在长文里。
- 属性库与正文库是只读挂载，坏了只影响正文，摘要与匹配照常工作。

## 五、公告同步

每天凌晨 3 点拉一次 JX3API 的最新公告，写 `news` 表并同步维护检索表。

- 按公告 id 去重，正文或标题变了才算更新；都没变只刷新抓取时间。
- 只动 `kind='news'` 的条目，不重建整库。
- 请求走配置里的 `api_base` 与 `proxy`，代理留空直连。
- 有新增或更新才重载词表；失败只记日志，不影响注入。

## 六、验收

- 闲聊里提到「荒血路」「跳车」「玄晶」，能自然接一句，不需要被问。
- 问库里没有的东西，用玩家口吻说记不清，不报错、不提资料库。
- 寒暄句不注任何条目（每轮那句固定提示仍在）。
- 连续 20 轮对话，注入总量不超预算，同一件事的细分不重复占位。
