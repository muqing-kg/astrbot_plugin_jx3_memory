# 设计

## 一、目标

聊天里冒出一个剑网3 的词，模型知道那是什么，能用玩家的话接下去。

不做的事：不做问答命令、不做关键词触发、不抢消息；不给人格设定，插件只提供事实；查不到就说不清楚，不暴露内部机制。

## 二、检索

不预先灌输，按需查：模型要回话时，拿当前消息和最近几条历史去碰词表，碰到才给。

- 匹配是**字面**的：首字分桶 + 子串判定，长词优先。词表全在内存，单条消息不到 3 毫秒。
- 不用向量：召回不准时塞错资料比不塞更糟。
- 多段文本之间用分隔符隔开再匹配，避免上段结尾与下段开头拼出并不存在的词。
- 词表是 `entry` 的主名加 `term` 里的别名，命中别名归一到主名（「跳车」→「跳车狗」）。简称不收，聊天里就接不住。
- 同名跨类型只留一个，顺序：门派 > 心法 > 技能 > 副本 > 首领 > 奇遇 > 通识 = 资料片 > 成就 > 任务 > 公告 > 物品。
- 物品、任务、成就里的两字名不进词表，「长安」「龙渊」这类既是地名也是任务名。
- 别名来源两类：心法自动去后缀（紫霞功 → 紫霞），副本名按「·」切段（冰火岛·荒血路 → 荒血路），其余靠手工表补。

## 三、注入

落点是 `req.extra_user_content_parts`，每块 `mark_as_temp()`：只对本次请求生效，不写进对话历史，也不改系统提示词。

文风：

```
（你玩了很久剑网3，下面这些是你本来就知道的东西。用得上的时候用自己的话说，
不要照抄，也不要提「资料」「条目」这类词。没提到的说明你不清楚，别猜。）

· 黑工：周常副本只能打一次，后面重置CD打的就算黑工……
```

- 第一人称记忆口吻，不编号、不标来源、不提示条数。
- 每条摘要 60 字以内，按句读收口，不留半句。
- 双闸门预算：条数上限 5、字数上限 1200，任一先到即停。
- 同一会话连续几轮命中同一批条目时不再重复注入；换会话或命中集合变化才重新给。
- 命中为空就一个字都不加。

## 四、存储

SQLite 单库 `data/memory.sqlite3`，随仓库一起下发，零第三方依赖。

- `entry(id, kind, name, brief, meta, body)`，`(kind, name)` 唯一。
- `term(word, entry_id)`：主名与别名混存，启动时一次性装进内存词表，之后每次请求只走内存匹配。
- 摘要生成时跳过正文开头的栏目小标题；正文为空才退回编辑备注。

## 五、公告同步

每天凌晨 3 点拉一次 JX3API 的最新公告，写 `news` 表并同步维护检索表。

- 按公告 id 去重，正文哈希变了才算更新；正文没变只刷新抓取时间。
- 只动 `kind='news'` 的条目，不重建整库。
- 请求走配置里的 `proxy`，留空直连。
- 有新增或更新才重载词表；失败只记日志，不影响注入。

## 六、验收

- 闲聊里提到「荒血路」「跳车」「玄晶」，能自然接一句，不需要被问。
- 问库里没有的东西，用玩家口吻说记不清，不报错、不提资料库。
- 寒暄句零注入。
- 连续 20 轮对话，注入总量不超预算，同批内容不重复堆叠。
