# 数据源实测清单

以下结论全部来自实际请求，不是文档转述。域名、路径、参数照抄即可用。

## 一、jx3box

`www.jx3box.com` 是 Vue 单页应用：直接抓 HTML 只能拿到空壳，`robots.txt` 与 `sitemap.xml` 也返回 SPA 页面，没有站点地图。数据只能走 API。

### 1. 物品（node.jx3box.com）

| 端点 | 说明 |
|---|---|
| `GET /api/node/item/count` | `total` 261,682 |
| `GET /api/node/item/list?last_id_key=N&per=50` | 返回 `idKey < N` 的最近 50 条，降序 |
| `GET /api/node/item/search?keyword=&per=` | 全文本搜索，返回 `total` |
| `GET /api/node/item/{id}` | 单条详情，如 `item/11_53` |
| `GET /api/node/item/menus` | 95 个分类，含 `query` 字段 |

分页有三条硬规则，实测得出：

- **`per` 被服务端忽略，恒返回 50 条。**传 100、200、500 都是 50。
- **普通分页硬上限 200 页，即 10,000 条。**`page=201` 起返回 `code: 10009`，提示改用游标。
- **游标是 `last_id_key`。**传上一页最后一条的 `idKey`，返回比它小的 50 条；`idKey` 连续无洞。传 0 报 `code: 10010`。

分类过滤参数（`AucSubType`、`AucGenre`、`Genre`、`TypeLabel`、`IsQuest`）对 `list` 无效，返回的仍是全量第一条，它们是前端菜单参数。

单条有效字段：`idKey`（整数序号）、`id`（如 `11_53`）、`Name`、`Quality`、`TypeLabel`、`Desc`（`<Text>text="..."` 形式）、`Genre`、`Level`。约 300 条记录的 `Name` 是空字符串，采集时应跳过。

### 2. 成就

`GET /api/node/achievement/list?page=N&per=50`，`per` 同样被忽略恒 50 条，但响应带 `total` 8498。无游标，靠 page 递增到空为止，400 页以内可拿完。

单条字段：`ID`、`Name`、`Point`、`General`、`Sub`、`Detail`、`Desc`、`SubAchievements`（管道分隔）。

### 3. 任务

`POST /api/node/quests`，**查询条件在 URL query 上，不是 body**：

```
POST /api/node/quests?page=1&map_id=X
```

响应结构不一致，取列表要兼容两种形状：

- `/quests` 的 `total`、`per`、`pages`、`page`、`list` 在**顶层**。
- `/quest/maps` 的列表套在 `data` 里。

任务接口不认 `last_id_key`，普通分页同样 10,000 条上限。绕法是先取 `GET /api/node/quest/maps`，按 `map_id` 分组翻页，每组都压在一万条以内。

单任务详情是 `GET /api/node/quest/?id=N`。注意 `/quest/41`、`/quests/41` 都返回 404。

### 4. 静态字典

`github.com/JX3BOX/jx3box-data` 仓库 `data/` 下共 43 个 JSON，合计约 1.3 MB，按原路径保存即可。

有用的：`xf/xf.json`（34 心法）、`xf/school.json`（21 门派）、`xf/schoolid.json`（门派 ID 映射）、`xf/mount_equip.json`（心法定位与主属性）、`xf/std/skill_name_id_level.json`（1,925 技能名）、`fb/fb_map.json`（大战 → 副本 → 首领）、`fb/dlc.json`（8 个资料片）、`serendipity/serendipity.json`（251 奇遇）。

不确定要不要的：`app/*.json` 是字段 schema 描述（`app/attr.json` 的键是英文属性名、值是中文「全属性」），`app/dict.json` 是简繁对照表，`server/*` 是服务器名，`xf/origin/*` 是缘起版数据。

### 5. 通识与黑话（cms.jx3box.com）

`GET /api/cms/helper/knowledge/count` 当前返回 0，已不可用；直接按类型取列表为准，实际共 536 条：jargon 260、bigbang 81、game 61、other 69、organization 18、gossip 13、player 9、castle 10、npc 15。

列表项带 `remark`，但那多是编辑备注（「初始化」「创建词条」），**正文要用 `GET /api/cms/wiki/post/id/{post_id}` 取**。个别条目会返回 500，跳过即可。

`GET /api/cms/posts?page=&per=` 是社区投稿，`total` 23,283，正文在 `post_meta`。

## 二、JX3API（公告）

| 项目 | 值 |
|---|---|
| 列表 | `GET https://www.jx3api.com/news/records?limit=N` |
| 信封 | 顶层 `{status, detail}`，不是 `{code, data}` |
| limit | 只认 1～50，`page` 参数被忽略 |
| 单条字段 | `catid`、`title`、`type`、`url`、`date`（`YYYY/MM/DD`）、`desc{id, asktime, inputtime, content（HTML）, title}` |

`desc.inputtime` 是 unix 秒，`asktime` 有空值，正文在 `desc.content` 且为 HTML。取时间戳按 `inputtime → asktime → date` 兜底。公告 id 取 `desc.id`。

## 三、实际采集量

| 数据 | 上游总量 | 实际取到 | 耗时 |
|---|---|---|---|
| 物品 | 261,682 | 261,385 | 12 段并发 228 秒 |
| 任务 | 20,387（735 个地图） | 20,387 | 十几分钟 |
| 成就 | 8,498 | 8,498 | 一分钟内 |
| 通识 | 536 | 535（1 条 500） | 半分钟 |
| 静态字典 | 43 个 JSON | 43 个 | 数秒 |

物品少掉的 297 条是 `Name` 为空的记录，上游本身没有可检索内容。

## 四、坑

- 先取 `count` 再决定是否全量抓，别按「页数未知」盲刷。
- 单页 50 条、约 9 KB；26 万条约 47 MB 原始 JSON，落盘前先把字段裁到需要的几个。
- 采集要能断点续跑：并发中途会碰到 `SSL: UNEXPECTED_EOF_WHILE_READING`，短退避撞不回来，退避区间要拉到 20 秒并加抖动。
- 没有公开的速率限制说明，默认 2～3 并发、错误退避，别用满。
- 写库时不要一边遍历游标一边插入，结果集会被冲掉，先 `fetchall()`。
- 任务文本覆盖主线与支线对白；CG 文案、配音台词、完整小说式剧情该源没有。
